# Retrieval baseline (synthetic corpus)

Source: `scripts/measure_retrieval.py`, results in `retrieval_baseline.json`.
Corpus: SYNTHETIC (generated by `scripts/generate_synthetic_corpus.py`, seed 1201). 164 documents, 951 chunks.

| Metric | Value | n |
|---|---|---|
| hit@3 overall (answerable tickets) | 91.7% | 240 |
| wrong refund policy version in top 3, NO filter | 78.3% | 60 refund tickets |
| wrong refund policy version in top 3, version filter on | 0.0% | 60 refund tickets |

What these numbers do NOT show:
- They measure retrieval only. Whether the final answer cites the wrong version is measured later by the integrated eval.
- Synthetic articles are templated, so FAQ hit@3 (100%) is optimistic compared with real help-centre text.
- The two refund policies are near-duplicates by construction, which inflates the unfiltered wrong-version rate relative to real documents.
- Order-status tickets score 10/30 (33%); see seam 4.
